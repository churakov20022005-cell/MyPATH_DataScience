# MyPATH · Data Science

Личная база знаний: три направления **SQL, Python, ML**, конспекты и вопросы
с ответами. Приложение на **Python / Flask + PostgreSQL**, архитектура **MVC**.

## Возможности

- Главная с тремя направлениями и последними записями.
- Отдельные страницы направлений, фильтры «Конспекты» / «Вопросы», поиск по заголовку, тексту и ответу.
- Страница материала; ответ на вопрос раскрывается по нажатию.
- Вход владельца, формы создания и редактирования, удаление с подтверждением.
- Хранение записей в PostgreSQL и постоянном томе Docker.
- Адаптивное оформление для телефона и компьютера.
- Чёрно-белая тема и подразделы внутри каждого направления: «Конспект ЯндексПрактикум», «Конспект по книгам», «Решение задач».
- Визуальный редактор Tiptap: заголовки, форматирование, списки, чек-листы, цитаты, маркер, ссылки, таблицы, блоки кода, фотографии, отмена и повтор.

## Полноценные конспекты

В форме создания/редактирования есть визуальная панель инструментов. Выделите
текст для жирного, курсива, подчёркивания, зачёркивания, маркера или ссылки.
Блок кода поддерживает выбор языка (SQL, Python, JavaScript, Bash, JSON),
моноширинный шрифт и отступ Tab. Код хранится как пример и не выполняется.
Ctrl+Enter выводит курсор из блока кода. Таблицы поддерживают добавление и
удаление строк/столбцов и переключение строки заголовков.

Фото можно загрузить кнопкой, перетащить в редактор или вставить из буфера.
Поддерживаются PNG/JPEG/WebP/GIF до **5 МБ** и 20 мегапикселей.
Изображения хранятся в PostgreSQL, поэтому не исчезают после перезапуска Render.
Приложение ограничивает их суммарный объём **100 МБ**, чтобы оставить место
в бесплатной базе. Это лимит приложения, а не дополнительный платный сервис.
Загрузить изображение может только владелец. Читать его могут посетители
сайта — как и опубликованный конспект. Новую запись нужно сохранить:
неприкреплённые изображения старше суток очищаются при следующей загрузке.

Существующие текстовые записи сохраняют прежний вид. При открытии в редакторе
они переводятся в редактируемые абзацы без выполнения HTML из старого текста.
Новые форматированные записи очищаются сервером по списку разрешённых тегов.
Форматирование доступно и для ответа на вопрос. Если JS не загрузился,
остаётся обычное поле ввода. Есть предупреждение при уходе с несохранённой записью;
автоматического сохранения нет.

После изменения структуры существующей базы выполните `init-db`:
миграция `002_rich_materials.sql` добавляет формат текста и таблицы изображений,
не переписывая старые конспекты.

### Разработка редактора

Готовый `app/static/editor.bundle.js` хранится в Git; при запуске на Render
достаточно существующей команды `pip install -r requirements.txt`.
Для изменения JavaScript установите Node.js и pnpm, затем:

```powershell
pnpm install
pnpm run build
```

Исходник: `frontend/editor.js`. Сборка также обновляет `editor-notices.txt`
с лицензиями используемых открытых компонентов. Пересобранные файлы из
`app/static/` нужно включить в коммит.

## Подразделы и обновление существующей базы

При открытии SQL, Python или ML сначала выберите подраздел. В форме создания
и редактирования записи есть поле «Подраздел». Поиск и фильтры работают внутри
выбранного подраздела; ссылка «Все материалы» показывает всё направление.
Записи, созданные до этого обновления, доступны через «Без раздела».
Чтобы распределить их, откройте запись и выберите подраздел при редактировании.

Команда `init-db` применяет идемпотентную миграцию
`app/migrations/001_material_sections.sql`: добавляет поле `section` и индекс,
сохраняя существующий текст и даты записей. Перед запуском новой версии на
существующей базе выполните `init-db` с прямым подключением PostgreSQL.

## Запуск на Windows

Нужны Python 3.13+ и работающий Docker Desktop с Linux containers.
В PowerShell из папки проекта:

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe configure.py
docker compose up -d --build
```

Открыть: **http://localhost:8000**.

Если `.env` уже создан, повторно запускать `configure.py` не нужно.
Скрипт не перезаписывает существующие настройки.

1. Нажмите **«Вход владельца»** внизу боковой панели или откройте `/login`.
2. Пароль находится в локальном файле `.owner-password.txt`.
3. Нажмите **«Добавить материал»**, выберите направление и тип записи.
4. Заполните заголовок и текст. Для вопроса можно добавить ответ позже.

На телефоне вход доступен напрямую по `/login`.
Пароль, `.env` и виртуальное окружение исключены из Git и Docker image.
После сохранения пароля в безопасном месте файл `.owner-password.txt` можно удалить.

По умолчанию база пустая. Необязательные учебные примеры:

```powershell
docker compose exec web python -m flask --app app seed-demo
```

Повторный запуск не дублирует примеры.
Остановить приложение без удаления записей: `docker compose down`.
Снова запустить: `docker compose up -d`.
Не используйте `docker compose down -v`, если хотите сохранить данные: `-v` удаляет том базы.

## MVC

```text
app/
  models.py        Model: соединение с PostgreSQL и SQL-запросы
  schema.sql       Таблица materials, ограничения и индекс
  controllers.py   Controller: маршруты, проверка форм, вход владельца
  templates/       View: HTML-шаблоны Jinja
  static/          CSS и небольшой JS для формы
  __init__.py      Фабрика приложения, CSRF, настройки и CLI
tests/
  test_app.py      Проверки маршрутов и интеграция с PostgreSQL
```

Поток запроса: браузер → контроллер → модель → PostgreSQL → модель → контроллер → шаблон → браузер.

`materials` хранит направление (`sql`, `python`, `ml`), тип (`note`, `question`),
заголовок, основной текст, ответ и даты создания/обновления.
Три фиксированных направления описаны в коде; записи хранятся в базе.
`init-db` создаёт отсутствующие таблицы и индекс, не удаляет существующие записи.
При будущих изменениях структуры понадобятся отдельные SQL-миграции.

Пользовательские значения передаются через параметры SQL. HTML из записей
выводится как текст. Для изменений требуются сессия владельца и CSRF-токен.

## Работа без контейнера приложения

Для разработки оставьте в Docker только PostgreSQL и откройте его порт
только на локальном компьютере:

```powershell
docker compose stop web
docker compose -f compose.yaml -f compose.local.yaml up -d db
.venv/Scripts/python.exe -m flask --app app init-db
.venv/Scripts/python.exe -m flask --app app run --port 8000
```

`.env` подхватывается автоматически. Для своей базы укажите
`DATABASE_URL=postgresql://user:password@host:5432/database`.

## Пароль и настройки

### Подключение к Neon

Для облачной базы задайте в локальном `.env` переменную `DATABASE_URL` строкой
подключения Neon, сохраняя параметры SSL из Neon Console. Для приложения можно
использовать pooled URL; прямое подключение при наличии хранится отдельно
в `DATABASE_URL_UNPOOLED`. Сайт использует `DATABASE_URL`, а создание таблиц
в `compose.neon.yaml` — прямое подключение `DATABASE_URL_UNPOOLED`.
Не добавляйте реальные строки подключения в README, исходники или Git.

Запуск приложения с Neon вместо локальной PostgreSQL:

```powershell
docker compose -f compose.neon.yaml up -d --build web
```

Команда заменяет контейнер сайта, но не удаляет локальную базу или её том.
Существующие локальные записи автоматически в Neon не переносятся.
Для возвращения к локальной базе используйте `docker compose up -d web`:
основной Compose задаёт локальный `DATABASE_URL` отдельно.

Проверка на Neon (временные схемы требуют прямого подключения):

```powershell
docker compose -f compose.neon.yaml exec web sh -c 'TEST_DATABASE_URL="$DATABASE_URL_UNPOOLED" python -m unittest discover -v'
```

На Render задайте `DATABASE_URL`, `SECRET_KEY`, `ADMIN_PASSWORD_HASH` и
`COOKIE_SECURE=true` через настройки Environment. Локальный `.env` не загружается в Git.

### Изменение пароля

Для ручной настройки скопируйте `.env.example` в `.env`.
Сгенерируйте `SECRET_KEY` и хеш пароля командами из комментариев в примере.
Хеш в `.env` заключите в одинарные кавычки: это сохраняет символы `$`
при чтении Docker Compose. После изменения настроек:

```powershell
docker compose up -d --force-recreate web
```

## Проверки

```powershell
.venv/Scripts/python.exe -m unittest discover -v
```

Без `TEST_DATABASE_URL` проверка реальной базы пропускается.
Полный прогон в контейнере с PostgreSQL:

```powershell
docker compose exec web sh -c 'TEST_DATABASE_URL="$DATABASE_URL" python -m unittest discover -v'
```

Интеграционный тест создаёт отдельную временную схему со случайным именем,
проверяет CRUD, поиск, повторную инициализацию, примеры и сохранение после
переподключения, затем удаляет только свою тестовую схему.

## Размещение в интернете

Локальный запуск доступен только с этого компьютера. Для публикации нужен
сервер/VPS или платформа, которая запускает Python-приложения и PostgreSQL.
Статический хостинг вроде GitHub Pages или Yandex Object Storage не запускает
серверную часть. Sites Worker не поддерживает прямое TCP-подключение
к PostgreSQL, поэтому приложение подготовлено для Docker-хостинга.

На сервере настройте HTTPS через reverse proxy, задайте `COOKIE_SECURE=true`,
используйте собственные секреты, резервное копирование PostgreSQL и ограничение
попыток входа на reverse proxy. Для доступа через reverse proxy измените привязку
порта в Compose согласно своей инфраструктуре. Локальный пароль не публикуйте.

`index.html` в корне — исходный статический макет. Рабочий сайт находится в `app/`
и открывается через сервер на порту 8000.
